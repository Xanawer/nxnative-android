# Phase 0 results and decisions

The probes of [PLAN.md](PLAN.md) Phase 0, run on the target phone: Nubia NX789J, Snapdragon 8 Elite (SM8750, Oryon CPU, Adreno 830), Android 16 (SDK 36), kernel 6.6, 4 KB pages, 16 GB, not rooted, no MTE. Each probe runs twice: as an NDK executable over `adb shell` (`u:r:shell`) and inside a NativeActivity APK with no Java code (`u:r:untrusted_app`). Details and raw numbers: [probes-cpu.md](probes-cpu.md) (P0.1–P0.6) and [probes-gpu.md](probes-gpu.md) (P0.7). The deciding probes (P0.2, P0.3) were rerun independently of the agent that wrote them, with the same results.

## Decisions

| # | Result | Decision |
|---|---|---|
| P0.1 Executable memory | PASS in the APK: anonymous RW → copy → `__builtin___clear_cache` → RX runs; so does re-JIT, and `PROT_EXEC` of a file in `nativeLibraryDir` (and, in this debuggable build, in the app's files directory) | The loader keeps the macOS path (`loader.c:518-556`: read, `mmap`, `mprotect` RX), plus `__builtin___clear_cache` over the text and patch area. The file-mapping fallback is not needed |
| P0.2 Thread slots | PASS in the APK with PLAN's candidate (b): `*(*(tpidr_el0 − 8) + 16*index + 8)`, bionic's `bionic_tls.key_data[index].data` reached through `TLS_SLOT_BIONIC_TLS`; 64 threads, nested threads, signal handlers. Candidate (a), initial-exec TLS, works only in an executable: bionic refuses to `dlopen` a library that uses it | The rewriter's `--target android` emits `mrs xT, tpidr_el0; ldur xT, [xT, #-8]` where Darwin has `mrs xT, tpidrro_el0` (one instruction more per stub); the key page holds `16*index + 8` instead of `8*key`. The startup check reads `0x1234` through the chain and dies otherwise (no `& ~7` mask). Every thread calls `pthread_setspecific` on the four keys before its first guest instruction: bionic clears a slot whose per-thread sequence number is stale (`pthread_key.cpp:174-180`), and a raw store from a stub does not set it. `libdmhost.so` is viable, so candidate (c), a child process, is not needed. `TLS_SLOT_APP` (`tp + 16`, one load fewer) is a possible later optimization, but it is a single word open to any library in the process |
| P0.3 Scratch below sp | PASS with a `sigaltstack`: `[sp − 112, sp)` intact under 850k signals and dirty-tracking write faults in the APK; SA_ONSTACK survives ART's libsigchain. Without one, the control corrupts it | The stubs keep their below-sp saves. Every thread that runs guest code has a `sigaltstack`, and every host handler is installed with SA_ONSTACK |
| P0.4 Pointer tagging | The executable's heap pointers carry tag `0xb4` (TBI, not MTE) until `mallopt(M_BIONIC_SET_HEAP_TAGGING_LEVEL, M_HEAP_TAGGING_LEVEL_NONE)`; the APK with `allowNativeHeapPointerTagging="false"` is untagged; `mmap` pointers are never tagged | The APK sets `allowNativeHeapPointerTagging="false"`; the executable calls the `mallopt` first thing in `main` |
| P0.5 x18 / tpidr_el0 | x18 is live and per thread (bionic's shadow call stack); `tpidr_el0` is the thread pointer | The x18 rewrite stays; the guest's `tpidr_el0` stays redirected to KTLS |
| P0.6 System registers | `cntfrq_el0` = 19.2 MHz, the Switch's rate; `ctr_el0` DminLine 4, which the rewriter's constant assumes; `cntpct_el0` traps (SIGILL); `cntvct_el0` readable and monotonic across cores | The counter gate stays (`cntpct` would trap, and `DM_DETCLOCK` needs it). Because the rates match, a later fast path could read `cntvct_el0` inline when the deterministic clock is off |
| P0.7 Placed GPU memory | **842.6** and **Turnip** pass: placed mapping at the requested address inside a `PROT_NONE` reservation, 6 GB placed in 512 MB chunks, chunks back to back with copies across the seam, unmap that keeps the range reserved, CPU bandwidth equal to anonymous memory, CPU/GPU coherence with no flush, `mprotect` write tracking (3–10 µs a fault). The **stock** driver has no `VK_EXT_map_memory_placed`. Two KGSL kernel bugs on all three drivers: after `mprotect` splits a GPU mapping, a page touched for the first time maps the wrong part of the object (a CPU store meant for one offset silently lands 2 MB away); and split GPU mappings never merge back (4,096 single-page unprotects left 8,193 VMAs for good; the limit is 65,530). 842.6 bugs: placed memory is never freed, `vkMapMemory` after a placed map returns a dead pointer, unmapping always re-reserves. Turnip: compute shaders read garbage from push constants. libadrenotools falls back to the system driver silently | **Strategy A on 842.6** (the default driver when the user has supplied it), **B on the stock driver**, Turnip second. A′ is out: it creates and frees placed memory per pool, which leaks on 842.6. Conditions for A: (1) `MADV_POPULATE_WRITE` every placed chunk before any `mprotect`, never `MADV_DONTNEED` it, and check a test page at startup, falling back to B if it reads wrong; (2) the dirty tracker works in 64 KB granules on placed memory and has a VMA budget, with a fallback when it runs out (Phase 2.2); (3) never free, unmap or `vkMapMemory` placed memory on 842.6; (4) chunks of 1 GB or less; (5) the whole heap is committed at startup (KGSL commits at allocation), so its size counts against memory pressure; (6) shader parameters go in buffers, not push constants (Turnip); (7) the host checks the loaded driver's identity (`driverID`, `driverInfo`) and shows it, since a failed custom load falls back silently. 842.6 is Qualcomm's package and cannot be redistributed: the user supplies it, as with game files. **Changed in Phase 2** (PLAN.md 2.2): B is brought up first on every target, after Stardew Valley's measurements; A on 842.6 follows as an optimization |
| P0.7b AHardwareBuffer pools (Galaxy Z Fold 7 `SM-F966B`, second device nubia `NX789J`; method from shirai91/nx2android, MIT; [probes-gpu.md](probes-gpu.md#ahardwarebuffer-backed-pools-zero-copy-buffers-on-the-stock-driver-2026-10-26)) | A BLOB AHB's dma-buf `mmap`ed `MAP_FIXED` over a guest range and imported as a dedicated `VkBuffer` works on the stock driver and on 842.6, in the exe and in the APK: GPU and CPU see each other's writes with no flush (descriptors and BDA), CPU bandwidth equals anonymous memory (95-111%), init over live data and finalize back to anonymous memory keep the data, write faults work (2.8-4.5 µs), the KGSL split-VMA bug does not occur (the mapping is fully populated at `mmap`), 100 init/finalize cycles give the memory back, 8,128 pools fit under the default fd limit. But: the mapping is a PFN map, so `process_vm_readv` (the host's `vm_read_overwrite`), shared futexes, `O_DIRECT` and all `madvise` fail on it (private futexes, `read`/`write`, LL/SC and LSE atomics work); split VMAs never merge, though mapping the fd again restores one VMA; each pool costs 4 fds and 3 VMAs. **An `isSupported` query above 64 MB aborted the system allocator service** (ubsan overflow in snapalloc) and restarted surfaceflinger and the framework; nothing above 64 MB was tried again | **Use with conditions, on the stock driver, for buffer pools up to 64 MB**, as an optimization of B (it removes only B's buffer shadows and their commit copies, about 0.27-0.38 ms a frame for Stardew Valley, where 60 fps already holds; textures are unchanged). Conditions: a constant cap of at most 64 MB per AHB (never probed with `isSupported`), larger pools stay on B; a `vm_read_overwrite` fallback that works on PFN maps (a `write()` into a pipe does); private futexes only, no `madvise` on pools; the same VMA budget for write tracking as KGSL, with the fd remap as defrag; fd and VMA budgets per pool; pool init and finalize on a quiescent range; never `vkMapMemory` the import. Not adopted for Stardew Valley now. **Second device, nubia NX789J** (stock `E031.47.18.49`, exe and APK; `--tests ahb` and the pool life cycle, with the checks tightened after review): every verdict matches the Fold 7; write faults are 2-3× slower (6.3-12.5 µs), `mprotect` and the fd remap about 2×; the decision is unchanged |
| P0.8 Shaders | Mac side: the 65 Stardew modules from `dmsh_xlate` are valid Vulkan 1.3 SPIR-V, but all declare unused `Float64`, `GroupNonUniform*` and (pixel shaders) `FragmentShaderPixelInterlockEXT`; `spirv-opt --trim-capabilities` leaves Ballot, Shuffle and the interlock. Device side ([probes-shader.md](probes-shader.md)): 65/65 modules and 73/73 pipelines (from the game's own effect definitions) build on stock, 842.6, Turnip and KosmicKrisp, stripped or not; cold 0.3–0.4 s for all 73 on a prime core, about 5 ms warm. Y: positive viewport height puts clip y < 0 on row 0. NaN: `FMax`/`FClamp`, which the translator emits, return the non-NaN operand on every driver (compute). Validation finds 9 clip/cull distances (limit 8) and a binding collision between the stages in set 0. Turnip's build loses render passes in GMEM mode (`TU_DEBUG=sysmem` works) | `dm/android/tools/spv_strip_caps.py` drops a capability when nothing in the module uses it, and the interlock extension with it: all 65 stay valid, left with Shader, ImageBuffer, ImageGatherExtended, ImageQuery, SampledBuffer and (vertex) DrawParameters. It becomes a stage of the Vulkan shader chain, with the rest of P0.8's list (PLAN.md 2.4): `N*` min/max, a smaller `gl_PerVertex`, one descriptor set per stage, Y handled in the backend, a pipeline cache per driver. Turnip stays second choice: its GMEM bug |
| P0.9 KosmicKrisp | Homebrew's `mesa` 26.2.5 ships it on macOS 26+ (Vulkan 1.4, Apple M5). It has `VK_EXT_external_memory_host` but not yet `VK_EXT_map_memory_placed` (Mesa main lists it); subgroups only in fragment and compute shaders; no geometry shaders, `shaderFloat64`, custom border colour, interlock or present-wait | The Mac loop is usable for API correctness with the validation layers. Its zero-copy path is host-pointer import, the phone's is placed mapping, so the backend's memory layer has both behind one interface |

## The Mac reference run (Phase 1's done-test)

`~/dm-work/android/ref/run_ref.sh <out> [secs]` (outside the repo: it names the user's game folders) boots Stardew Valley on the Mac host with a fresh save, `DM_DETCLOCK=16666667`, `DM_FIXED_TIME=1767225600`, `DM_KEYS="f1500:A,f1800:A"` and screenshots at fixed frames: the title is up by frame 1400 and character creation by frame 2300, with no `[RED]` line. `dm/android/tools/lognorm.py` normalizes a log (addresses, paths, numbers; backend-tagged and statistics lines dropped). Two Mac runs give the same normalized log, whole and `--until-present`, which is its self-test. Pixels are not deterministic: the same frame of two runs differs in 2–37% of its pixels, `DM_DETCLOCK_PACE=1` included, so screens are compared by eye.
